# Расписание MiM ВШМ СПбГУ — телеграм-бот

Бот забирает расписание программы Master in Management с
[timetable.spbu.ru](https://timetable.spbu.ru), спрашивает у студента язык и
фамилию, а дальше показывает **только его занятия** — с учётом распределения по
когортам. Ещё он хранит заметки и присылает их в тот день, который вы назвали.

## Что умеет

**Два языка.** Первым делом бот спрашивает язык — русский или английский. Выбор
меняет и интерфейс, и сам сайт: расписание запрашивается с переключённой
культурной кукой, поэтому названия занятий приходят на выбранном языке. Дату для
заметки тоже можно написать по-английски: `tomorrow`, `in 3 days`, `on Friday`,
`September 5`. Язык переключается в настройках или командой `/language`.

**Знакомство по фамилии.** Первое, что спрашивает бот, — фамилия. По списку
программы он находит студента и его когорты:

```
Corporate Finance — Coh.2      Research Seminar I — 1
Organizational Behaviour — Coh.2   Cross-Cultural Management — 1
QMBR, лекции — Coh.2           MPS I — Shevchuk 2
QMBR, семинары — Coh.4
```

Фамилию можно писать по-русски или латиницей: «Юрченко» найдёт `Iurchenko`,
опечатки тоже прощаются. Если фамилия не нашлась или студента нет в списке —
бот покажет расписание всей программы целиком.

**Расписание своей когорты.** На сайте деление потока подписано как
«Подгруппа 2», а у предмета MPS I когорты разведены по преподавателям. Бот
убирает занятия чужих когорт и подписывает, сколько скрыл. Фильтр выключается в
настройках одной кнопкой.

**Своя подгруппа у преподавателя.** У MPS I поток делят между
преподавателями, и у одного преподавателя может быть две подгруппы. В
ведомости деканата они пронумерованы внутри преподавателя («Shevchuk 1»,
«Shevchuk 2»), а на сайте — по всему потоку («Подгруппа 2», «Подгруппа 4»).
Сопоставить одно с другим нельзя, поэтому бот спрашивает студента — и
показывает время занятий каждой подгруппы, чтобы было по чему узнать свою.
Вопрос задаётся, только когда выбор действительно есть; пока выбор не
сделан, показываются пары обеих подгрупп своего преподавателя, но не чужих.

**Свой иностранный язык.** Языковые пары в ВШМ идут параллельными потоками: в
один слот стоят испанский, немецкий, французский и русский как иностранный,
причём у популярных языков по две группы с разными преподавателями. Бот
спрашивает, какой язык вы изучаете, — список берётся из живого расписания, так
что предлагается ровно то, что там есть. Если у языка несколько групп, бот
уточнит преподавателя. В типичный понедельник это убирает из расписания 10 пар
из 15. Есть варианты «показывать все» и «не изучаю».

**Расписание поменялось — бот скажет сам.** Сайт об изменениях не сообщает,
поэтому бот раз в три часа сам сверяет ближайшие две недели с тем расписанием,
которое вы видели в прошлый раз, и присылает только разницу: что добавилось,
что убрали, что перенесли и где сменилась аудитория или преподаватель.
Сравнение идёт уже после фильтров, то есть о чужих когортах и чужих языках вас
не побеспокоят. Ночью (с 22:00 до 8:00) бот молчит и переносит проверку на
утро, а первая проверка и смена настроек фильтра проходят без сообщения — иначе
собственное переключение выглядело бы как изменение расписания. Выключается
кнопкой в настройках.

**Рассылка** — «раз в день» (на сегодня), «раз в неделю» (по понедельникам на
всю неделю) или «раз в месяц» (первого числа на весь месяц), в выбранное время.

**Заметки** — пришлите боту любой текст, и он спросит, когда о нём напомнить.
Дату можно выбрать кнопкой (сегодня / завтра / послезавтра / через неделю) или
написать словами: `05.09`, `05.09.2026 18:30`, `5 сентября`, `через 3 дня`,
`в пятницу`. Одной строкой тоже работает: `/note 05.09 18:30 сдать эссе`.

### Команды

| Команда | Что делает |
| --- | --- |
| `/start` | Начало работы и ввод фамилии |
| `/setup` | Указать фамилию заново |
| `/cohorts` | Показать мои когорты |
| `/today`, `/tomorrow` | Расписание на сегодня / завтра |
| `/week`, `/nextweek` | Расписание на эту / следующую неделю |
| `/note` | Новая заметка (можно сразу: `/note завтра позвонить научруку`) |
| `/notes`, `/delnote N` | Список заметок и удаление |
| `/language` | Переключить язык интерфейса |
| `/settings` | Язык, иностранный язык, подгруппа, периодичность, время, фильтр, слежение за изменениями, смена фамилии |
| `/stop` | Отключить рассылку |

## Запуск

```bash
git clone https://github.com/sheeshlove/timetable_spbu.git
cd timetable_spbu

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env         # и вписать BOT_TOKEN от @BotFather
python -m bot
```

Настройки читаются из переменных окружения или файла `.env`:

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `BOT_TOKEN` | — | Токен от [@BotFather](https://t.me/BotFather), обязателен |
| `GROUP_ID` | `474489` | Учебная группа MiM на сайте расписания |
| `DIVISION_ALIAS` | `GSOM` | Псевдоним подразделения в адресах сайта |
| `PROGRAM_TITLE` | `Master in Management, 2026` | Подпись программы в сообщениях |
| `ROSTER_PATH` | — | Путь к списку студентов, если он лежит вне репозитория |
| `DB_PATH` | `data/bot.sqlite3` | Файл базы SQLite |
| `TZ_NAME` | `Europe/Moscow` | Часовой пояс, в котором пользователь задаёт время |
| `TIMETABLE_BASE_URL` | `https://timetable.spbu.ru` | Адрес сайта расписания |
| `HTTP_CACHE_TTL` | `900` | Сколько секунд кэшировать ответы сайта |
| `HTTP_TIMEOUT` | `20` | Таймаут запроса к сайту, секунды |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

### На сервере

Полная инструкция по развёртыванию — от чистой VPS до автозапуска, бэкапов и
разбора неполадок — в [DEPLOY.md](DEPLOY.md). Коротко:

```bash
git clone https://github.com/sheeshlove/timetable_spbu.git /opt/timetable_spbu
cd /opt/timetable_spbu
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env          # вписать BOT_TOKEN
cp deploy/timetable-bot.service /etc/systemd/system/
systemctl enable --now timetable-bot
```

Есть и вариант с Docker: `docker compose up -d --build`.

## Обновление списка студентов

Список когорт лежит в `bot/roster/mim_2026.json` и собирается из таблицы
деканата:

```bash
pip install -r requirements-dev.txt
python scripts/import_cohorts.py Cohorts_Distribution_MiM_2026.xlsx
```

Список — персональные данные 85 человек. Если репозиторий публичный, держите
файл вне git: положите его рядом с базой и укажите `ROSTER_PATH` в `.env`.

Скрипт ждёт колонки `No.`, `Name, Last Name` и по одной на предмет
(`Corp. Finance`, `Org. Behaviour`, `QMBR lectures`, `QMBR seminars`, `RS I`,
`CCM`, `MPS I`), выводит сводку по когортам и убирает строки-дубли. Если
деканат переименует предмет или добавит новый, правьте список `SUBJECTS` в
начале скрипта — там же задаются подстроки, по которым занятие в расписании
относят к предмету.

## Как устроено

```

├── changes.py         сравнение слепков: что изменилось с прошлой проверки
├── scheduling.py      расчёт следующей рассылки (день/неделя/месяц)
├── scheduler.py       фоновый «тикер»: раз в минуту отправляет то, чему пора
├── dates.py           разбор дат из текста пользователя (ru/en)
├── i18n.py            переводы интерфейса и локализованные даты
├── languages.py       изучаемый иностранный язык и отбор языковых пар
├── middleware.py      подстановка языка пользователя в хендлеры
├── formatting.py      тексты сообщений
├── keyboards.py       клавиатуры
├── handlers/
│   ├── setup.py       знакомство: фамилия, периодичность, время
│   ├── schedule.py    расписание по запросу и меню настроек
│   └── notes.py       заметки
├── roster/

│   └── mim_2026.json  выгрузка из таблицы деканата
└── timetable/
    ├── client.py      HTTP-клиент: кэш, повторы, выбор источника данных
    ├── api.py         разбор JSON-API сайта
    ├── scraper.py     резервный разбор HTML
    └── models.py      доменные модели

scripts/
├── probe_site.py           проверка сайта расписания и отбора пар
├── check_telegram.py       проверка связи с Telegram (и через прокси)

```

Несколько решений, которые стоит знать при доработке:

* **Язык уходит и на сайт.** У каждого языка своя HTTP-сессия: бот один раз
  отправляет форму `/Base/SetClientCultureCookie`, сайт ставит куку культуры, и
  дальше страницы приходят на нужном языке. Кэш ответов тоже разделён по языку.
  Если переключение не сработает, останется заголовок `Accept-Language`.
* **Список языков не захардкожен.** Какие языки предлагать и какие у них
  группы, бот выясняет из ближайших двух недель расписания. Если сайт не
  ответил, показывается обычный набор — испанский, немецкий, французский,
  английский, русский как иностранный.
* **Номер из ведомости и номер на сайте — разные нумерации.** Для предметов,
  где группу задаёт преподаватель (MPS I), ведомость нумерует группы внутри
  преподавателя, а сайт — подгруппы по всему потоку. Раньше бот сравнивал их
  напрямую, и студенты «Shevchuk 2» попадали на пары первой группы. Теперь
  номер из ведомости для этого не используется вовсе: фамилия преподавателя
  отбирает пары надёжно, а какая из его подгрупп своя — знает только сам
  студент, и бот его спрашивает (`educator_subgroups` в
  `bot/roster/filtering.py`).
* **Фильтр когорт намеренно осторожен.** Занятие скрывается, только если по
  тексту видно, что оно принадлежит *другой* когорте: есть метка вида «Coh.1»,
  «группа 2» или фамилия чужого преподавателя, и это значение вообще
  встречается у этого предмета. Нет метки, непонятная метка, предмет не из
  таблицы — занятие показывается. Пропущенная пара хуже лишней.
* **Одна программа — один идентификатор группы.** Выбора подразделения,
  программы и года нет: бот обслуживает MiM, группа задаётся в `GROUP_ID`.
* **Два источника данных.** Сначала бот идёт в JSON-API (`/api/v1/...`), а если
  тот недоступен или отдал пустоту — разбирает HTML страницы расписания.
* **Рассылка — один «тикер», а не задача на пользователя.** Раз в минуту
  `Scheduler.tick()` спрашивает у базы, кому пора. Время следующей отправки
  лежит в SQLite, поэтому перезапуск бота ничего не теряет: пропущенная за
  время простоя рассылка уйдёт при первом же такте. Если сайт не ответил,
  слот не пропадает — попытка повторится через 15 минут.
* **Изменения ловятся слепками.** Push-уведомлений у сайта нет, поэтому бот
  хранит в базе то расписание, которое студент видел в прошлый раз (уже после
  фильтров), и сравнивает с ним свежее. Сравнение ограничено пересечением окон:
  окно «сегодня + 14 дней» каждый день уезжает вперёд, и без этого вчерашние
  пары выглядели бы отменёнными, а появившиеся на горизонте — добавленными.
  Пара «предмет + поток» в другое время считается переносом, а не парой
  «убрали/добавили». Если ключ фильтра (фамилия, язык, режим «показывать всё»)
  изменился, старый слепок несравним: бот молча запоминает новый. Группа у всех
  одна, поэтому за один проход бот скачивает расписание один раз на язык
  интерфейса, а не по разу на студента.
* **Telegram может быть недоступен с сервера.** С российских хостингов
  `api.telegram.org` часто блокируется, причём непостоянно. На этот случай
  есть `TELEGRAM_PROXY`: через прокси ходит только Telegram, за расписанием
  бот обращается напрямую. Обновление меню команд при старте не считается
  обязательным — если сети нет, бот всё равно поднимается и подхватит связь,
  когда она вернётся.
* **Часовые пояса.** В базе всё в UTC, пользователю показывается локальное
  время; переводы времени и високосные годы обрабатывает `zoneinfo`.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

278 тестов: переводы, отбор языковых пар, сравнение слепков расписания, поиск по фамилии с транслитерацией, отбор занятий по
когортам на настоящей странице сайта, парсеры JSON и HTML, выбор источника
данных, расчёт расписания рассылок, хранилище с миграциями, разбор русских и
английских дат и сквозные сценарии диалога на обоих языках — последние гоняют
настоящий `Dispatcher` aiogram через поддельный Telegram
(`tests/fake_telegram.py`), так что проверяется вся цепочка от нажатия кнопки
до записи в базу.

## Если сайт изменил вёрстку

Расписание — чужой сайт, и его разметка иногда меняется. Диагностика:

```bash
python scripts/probe_site.py --alias GSOM --group 474489
```

Скрипт покажет, какой источник работает (`✅`/`❌`), что удалось распарсить и
**переключается ли язык**: он забирает неделю дважды, по-русски и по-английски,
и сравнивает названия занятий. Совпали — значит культурная кука не сработала.
Чтобы сохранить живые ответы и превратить их в фикстуры для тестов:

```bash
python scripts/probe_site.py --dump tests/fixtures
```

Дальше правится `bot/timetable/api.py` (если поменялся JSON) или
`bot/timetable/scraper.py` (если HTML).

> **Замечание о проверке.** HTML-парсер и правила распознавания когорт написаны
> по настоящей странице недели (она лежит в `tests/fixtures/week_page_ru.html`),
> на ней же гоняются тесты. А вот сходить на живой сайт из среды сборки не
> вышло: `timetable.spbu.ru` закрыт сетевой политикой. Непроверенными остались
> JSON-API и переключение языка кукой — и то и другое проверяется одной
> командой `scripts/probe_site.py` перед запуском в бой.
