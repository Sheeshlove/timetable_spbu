# Расписание СПбГУ — телеграм-бот

Бот забирает расписание с [timetable.spbu.ru](https://timetable.spbu.ru), помогает
кнопками выбрать свою группу и присылает расписание с выбранной периодичностью:
раз в день, раз в неделю или раз в месяц. Ещё он хранит заметки и присылает их
в тот день, который вы назвали.

## Что умеет

**Выбор группы кнопками** — четыре шага, каждый со страничной навигацией и поиском
по названию:

```
Направление (подразделение) → Программа → Год поступления → Группа
```

Шаг с группой пропускается, если у года поступления она одна.

**Рассылка расписания** — «раз в день» (на сегодня), «раз в неделю» (по
понедельникам на всю неделю) или «раз в месяц» (первого числа на весь месяц).
Время отправки выбирается кнопками, часовой пояс — из настроек (по умолчанию
`Europe/Moscow`).

**Заметки** — пришлите боту любой текст, и он спросит, когда о нём напомнить.
Дату можно выбрать кнопкой (сегодня / завтра / послезавтра / через неделю) или
написать словами: `05.09`, `05.09.2026 18:30`, `5 сентября`, `через 3 дня`,
`в пятницу`. Одной строкой тоже работает: `/note 05.09 18:30 сдать эссе`.

### Команды

| Команда | Что делает |
| --- | --- |
| `/start` | Начало работы и выбор группы |
| `/setup` | Выбрать группу заново |
| `/today`, `/tomorrow` | Расписание на сегодня / завтра |
| `/week`, `/nextweek` | Расписание на эту / следующую неделю |
| `/note` | Новая заметка (можно сразу: `/note завтра позвонить научруку`) |
| `/notes`, `/delnote N` | Список заметок и удаление |
| `/settings` | Периодичность, время рассылки, смена группы |
| `/stop` | Отключить рассылку и удалить настройки |

## Запуск

```bash
git clone https://github.com/sheeshlove/timetable_spbu.git
cd timetable_spbu

python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env         # и вписать BOT_TOKEN от @BotFather
python -m bot
```

Настройки читаются из переменных окружения или файла `.env`:

| Переменная | По умолчанию | Значение |
| --- | --- | --- |
| `BOT_TOKEN` | — | Токен от [@BotFather](https://t.me/BotFather), обязателен |
| `DB_PATH` | `data/bot.sqlite3` | Файл базы SQLite |
| `TZ_NAME` | `Europe/Moscow` | Часовой пояс, в котором пользователь задаёт время |
| `TIMETABLE_BASE_URL` | `https://timetable.spbu.ru` | Адрес сайта расписания |
| `HTTP_CACHE_TTL` | `900` | Сколько секунд кэшировать ответы сайта |
| `HTTP_TIMEOUT` | `20` | Таймаут запроса к сайту, секунды |
| `LOG_LEVEL` | `INFO` | Уровень логирования |

### Как демон systemd

```ini
[Unit]
Description=SPbU timetable telegram bot
After=network-online.target

[Service]
WorkingDirectory=/opt/timetable_spbu
ExecStart=/opt/timetable_spbu/.venv/bin/python -m bot
EnvironmentFile=/opt/timetable_spbu/.env
Restart=always

[Install]
WantedBy=multi-user.target
```

## Как устроено

```
bot/
├── __main__.py        точка входа: сборка Dispatcher, запуск polling и рассылки
├── config.py          настройки из окружения
├── storage.py         SQLite: подписки и заметки
├── scheduling.py      расчёт следующей рассылки (день/неделя/месяц)
├── scheduler.py       фоновый «тикер»: раз в минуту отправляет то, чему пора
├── dates.py           разбор дат из текста пользователя
├── formatting.py      тексты сообщений
├── keyboards.py       клавиатуры
├── handlers/
│   ├── setup.py       мастер выбора группы, периодичность, время
│   ├── schedule.py    расписание по запросу и меню настроек
│   └── notes.py       заметки
└── timetable/
    ├── client.py      HTTP-клиент: кэш, повторы, выбор источника данных
    ├── api.py         разбор JSON-API сайта
    ├── scraper.py     резервный разбор HTML
    └── models.py      доменные модели
```

Несколько решений, которые стоит знать при доработке:

* **Два источника данных.** Сначала бот идёт в JSON-API (`/api/v1/...`), а если
  тот недоступен или отдал пустоту — разбирает HTML тех же страниц. Логика
  переключения живёт в `TimetableClient`, парсеры чистые и покрыты тестами.
* **Рассылка — один «тикер», а не задача на пользователя.** Раз в минуту
  `Scheduler.tick()` спрашивает у базы, кому пора. Время следующей отправки
  лежит в SQLite, поэтому перезапуск бота ничего не теряет: пропущенная за
  время простоя рассылка уйдёт при первом же такте. Если сайт не ответил,
  слот не пропадает — попытка повторится через 15 минут.
* **Списки в кнопках.** В `callback_data` Telegram помещается 64 байта, поэтому
  туда уходит индекс варианта, а сам список лежит в состоянии диалога.
  Если состояние потеряно (например, бот перезапустили посреди выбора), бот
  предложит начать заново.
* **Часовые пояса.** В базе всё в UTC, пользователю показывается локальное
  время; переводы времени и високосные годы обрабатывает `zoneinfo`.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest
```

99 тестов: парсеры JSON и HTML, выбор источника данных, расчёт расписания
рассылок, хранилище, разбор дат и сквозные сценарии диалога — последние гоняют
настоящий `Dispatcher` aiogram через поддельный Telegram (`tests/fake_telegram.py`),
так что проверяется вся цепочка от нажатия кнопки до записи в базу.

## Если сайт изменил вёрстку

Расписание — чужой сайт, и его разметка иногда меняется. Диагностика:

```bash
python scripts/probe_site.py --alias GSOM --group 474489
```

Скрипт покажет, какой источник работает (`✅`/`❌`) и что удалось распарсить.
Чтобы сохранить живые ответы и превратить их в фикстуры для тестов:

```bash
python scripts/probe_site.py --dump tests/fixtures
```

Дальше правится `bot/timetable/api.py` (если поменялся JSON) или
`bot/timetable/scraper.py` (если HTML). Остальной код парсеров не касается.

> **Замечание о проверке.** Код парсеров писался по описанной структуре сайта:
> в среде, где бот собирался, `timetable.spbu.ru` заблокирован сетевой политикой,
> поэтому запросы к живому сайту не выполнялись. Тесты гоняются на фикстурах.
> Перед первым запуском в бой прогоните `scripts/probe_site.py` — он за минуту
> покажет, совпали ли реальные адреса и разметка с ожидаемыми.
